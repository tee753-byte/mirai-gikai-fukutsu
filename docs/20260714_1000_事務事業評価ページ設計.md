# 福岡県版「事務事業評価」ページ設計

作成日: 2026-07-14

## 1. 背景・目的

福岡市版みらい議会に実装済みの事務事業評価ページ（`/jimu-jigyo`）と同等の機能を、
福岡県版に追加する。県が毎年公表する行政評価（令和7年度: 事務事業評価266事業＋
公共事業再評価47事業）を、事業ごとのカード一覧・フィルタ・詳細ページ
（KPI推移チャート・予算推移チャート付き）として可視化する。

- 県公式ページ: https://www.pref.fukuoka.lg.jp/contents/gyouseihyouka-01.html
- 市版実装（移植元）: fukuoka-city リポジトリ `web/src/features/jimu-jigyo/`

## 2. 決定事項

1. **データ保存は Supabase**（市版同様の raw_data JSONB 方式）。市版で欠けていた
   再現可能な投入seedスクリプトを県版では必ず整備する
2. **スコープは事務事業評価266事業＋公共事業再評価総括表**（政策事前評価113事業・
   研究開発・森林環境税は対象外）
3. **事業費推移はR5〜R7の3年分の評価書を突合して5年分**（R4決算〜R8当初）を構築
4. **県公式の見直し区分（継続〔拡充/改善/一部改善/縮小〕・終了〔完了/再構築/廃止〕）を
   主軸バッジ＋フィルタ**とし、市版のKPI/予算/効率の3軸方向分析（↑↓→）も再現して併記
5. トップページは市版と同じ形（バナー＋アーカイブセクション）で組み込む
6. 一覧ページに部局・見直し区分・キーワードのフィルタ

## 3. データソースの構造（調査結果）

### 様式1号（事務事業評価書、1事業2〜3ページ、5分冊PDF）

- ヘッダ: 事業名／部／課(室)／事業開始年度
- 総合計画位置づけ: 4つの柱・中項目・小項目・具体的な取組
- １ 事業のねらい・目的（自由記述）
- ２ 事業概要（スキーム図が多くテキスト抽出不能 → 概要一覧の「事業の内容」列で代替）
- ３ 成果指標及び進捗状況: 指標ごとに**R2〜R12の目標・実績**の表＋設定根拠＋
  R6実績評価と要因＋目標見直し有無＋効率化工夫
  （= **KPI推移は最新年度PDFだけで複数年分取れる**）
- ４ 事業費（千円）: R6決算・R7当初・R8当初（＋まれに補正列）、うち一般財源、
  人件費（時間・千円）×3年
- ５ 見直しの内容: 区分の選択印＋理由＋見直し内容

### 概要一覧（1.37MB PDF）

266事業の要約表（No／事業名・担当部局・課／R7事業費／ねらい／内容／主な指標／見直し区分）。
様式1号とは独立に作られているため**クロスチェックの照合先**として使う。

### 公共事業再評価総括表（様式3号）

長期継続中の公共事業47件の再評価一覧。事務事業評価266件とは**別の評価類型**で紐付かない。
一覧ページの別タブとして表示する（詳細ページなし）。

## 4. データ化パイプライン（本PR・実装済み）

`tools/jimu-jigyo-pdf/` ＋ `.claude/skills/jimu-jigyo-pdf/SKILL.md`。
AI不使用・pdfplumber座標ベース。詳細はSKILL.md参照。

- `extract_gaiyou.py` → `docs/data/jimu-jigyo/r7/gaiyou.json`（266件）
- `extract_hyoka.py` → `docs/data/jimu-jigyo/r7/items.json`（266件）
  - 罫線画像化シート対応のため表は単語座標グリッドで復元
  - 見直し区分の選択印は矩形枠／楕円／塗り矩形／画像スタンプの4方式を図形検出
- `extract_saihyoka.py` → `docs/data/jimu-jigyo/r7/saihyoka.json`（47件）
- `crosscheck.py`: 概要一覧×様式1号を266件全件突合
  （事業名・部局・R7事業費・見直し区分）＋内部整合＋再評価件数

**検証結果（R7）: FAIL=0**。WARN6件はすべて原典由来
（公式資料間の事業名表記ゆれ5件・原典の一般財源＞歳出1件）。
既知の限界: No.237は指標表が画像のため抽出不可（概要一覧の指標テキストで代替）、
指標が自由記述のシート17件は `進捗状況テキスト` に格納。

## 5. DBスキーマ（次PR）

新規migration（4テーブル、市版の10テーブル構成から簡素化）:

- `jimu_jigyo_bureaus`: code(PK) / name / display_order
- `jimu_jigyo_items`: id(UUID) / slug(UNIQUE) / name / bureau_code(FK)
- `jimu_jigyo_evaluations`: item_id(FK) / fiscal_year / **raw_data JSONB** /
  review_category(GENERATED) / source_pdf / source_page / UNIQUE(item_id, fiscal_year)
- `jimu_jigyo_reevaluations`: slug / fiscal_year / raw_data JSONB / UNIQUE(slug, fiscal_year)

RLSは有効化のみ・ポリシーなし（`createAdminClient()` 経由）。
分析（3軸）はDBに持たせず、webのloaderで純関数計算する
（266件はms単位・seed/webの二重管理を避ける）。

## 6. feature構成（後続PR）

`web/src/features/jimu-jigyo/`（市版をベースにコピー・県データ形状へ適応）:

- `shared/types/jimu-jigyo.ts` — 県版型（見直し区分・総合計画位置づけ・人件費等）
- `shared/utils/analysis.ts` — 3軸分析: KPI=実績R6/目標R6、予算=R6決算vsR5決算、
  効率=達成率平均÷歳出の前年比。閾値±5%は市版踏襲
- `shared/utils/review-category.ts` / `filter.ts` — 新規純関数（テスト必須）
- `server/loaders/load-jimu-jigyo-list.ts` — YEAR_METADATA定数＋Mapメモ化
- `client/components/` — カード（見直し区分バッジ主軸）・KPI折れ線・予算積み上げ棒（recharts）

URL: `/jimu-jigyo`（年度一覧）／`/jimu-jigyo/r7`（一覧＋フィルタ
`?bureau=&category=&q=`、`?view=saihyoka` で再評価タブ）／`/jimu-jigyo/r7/[slug]`（詳細）／
`/jimu-jigyo/about-score`（見方解説）。ルートは `web/src/app/(main)/jimu-jigyo/` 配下。

トップページ: `jimu-jigyo-banner.tsx`（GeneralQuestionsBannerの下）＋
`jimu-jigyo-archive-section.tsx`（記者会見アーカイブの後）。

## 6.5 一覧ページのフィルタUI詳細設計

266件を快適に絞り込むための設計。すべて `Link` ＋ searchParams のRSC完結
（クライアントJS不要・URL共有可能・戻るボタンで状態復元）。

### レイアウト（上から順）

```
┌─────────────────────────────────────────────┐
│ 事務事業評価（令和7年度）           h1        │
│ 説明文・免責・「この分析の見方 →」            │
├─────────────────────────────────────────────┤
│ サマリーカード: 総事業数266 / 継続227 /       │
│ 終了39 / 総事業費                            │
├─────────────────────────────────────────────┤
│ タブ: [事務事業評価 266] [公共事業再評価 47]  │←?view=
├─────────────────────────────────────────────┤
│ 🔍 [事業名・課室で検索________] [検索]        │←?q=
│ 部局:   [全て][総務部 7][企画・地域振興部 18] │←?bureau=
│         [人づくり 27]…[警察本部 13]          │
│ 見直し: [全て 266][継続 227][終了 39]        │←?category=
│   （継続選択時）[拡充 26][改善 4]            │
│                [一部改善 161][縮小 36]       │
│   （終了選択時）[完了 23][再構築 9][廃止 7]   │
├─────────────────────────────────────────────┤
│ 161件（全266件中） ［条件をクリア×］          │
│ ┌カード┐ ┌カード┐ ┌カード┐                  │
└─────────────────────────────────────────────┘
```

### 部局フィルタ（?bureau=）

- **親部局12分類**のピル（局は親部局に集約: 総務部防災危機管理局→総務部、
  商工部観光局→商工部 等）。全266件が12分類でカバーできることをデータで確認済み
  （最大は商工部51件）。カード上は「商工部観光局」等の詳細名をそのまま表示する
- 並び順は県の組織順で固定: 総務部→企画・地域振興部→人づくり・県民生活部→
  保健医療介護部→福祉労働部→環境部→商工部→農林水産部→県土整備部→建築都市部→
  教育庁→警察本部（データ由来の動的生成ではなく定数。`shared/utils/bureau.ts`）
- 各ピルに件数バッジ（現在の他フィルタ適用後の件数ではなく**全体件数**を表示。
  件数が変動すると位置がズレて押しづらいため）
- slug: `?bureau=somu` 等のローマ字コード（URLに日本語を出さない）

### 見直し区分フィルタ（?category=）

- **2段階**: 大区分ピル（全て/継続/終了）を常時表示し、大区分を選ぶと
  その小区分ピルが下に展開される（サーバーレンダリングで出し分け）
  - `?category=keizoku` → 継続すべて。小区分行: [すべて][拡充][改善][一部改善][縮小]
  - `?category=keizoku-kakuju` → 継続（拡充）のみ
  - `?category=shuryo-haishi` → 終了（廃止）のみ
- 7小区分を最初から全部並べない理由: 部局12ピルと合わせるとフィルタ帯が
  縦に膨らみ、モバイルでカードが画面外に追いやられるため
- ピルの色は区分バッジと同系色（下記トークン）で視覚的に対応付ける

### キーワード検索（?q=）

- `<form method="get">` ＋ `<input name="q">`（Search アイコン、
  placeholder「事業名・課室で検索」）。JSなしで動作
- form内に `bureau`・`category`・`view` の hidden input を置き、
  検索実行時に他のフィルタ条件を維持する
- 対象フィールド: 事業名・課室（正規化して部分一致）。
  絞り込みロジックは `shared/utils/filter.ts` の純粋関数＋テスト

### モバイル（<sm）の畳み方

- **部局ピル行は横スクロール1行**（`flex overflow-x-auto` ＋ スクロールバー非表示、
  sm以上で `flex-wrap` の複数行に切替）。アコーディオンに畳むより1スワイプで
  届く方が速く、選択中ピルが行内に見え続ける
- 見直し区分の大区分3ピル＋小区分は幅が小さいので折り返しのみ
- 検索フォームは全幅

### 適用中フィルタの明示

- 件数表示「N件（全266件中）」＋ フィルタ適用時のみ「条件をクリア ×」リンク
  （`basePath` へのLink）
- 0件時: 「条件に一致する事業がありません」＋クリアリンク

### 公共事業再評価タブ（?view=saihyoka）

- タブUIはピルより一段大きいセグメント（件数付き）。再評価タブでは
  事務事業評価用フィルタ帯を出さない（47件・カードに全情報で詳細ページなし）

### 見直し区分バッジの色トークン（globals.css に追加）

| 区分 | トーン | 用途 |
|---|---|---|
| 拡充 | 緑系 | 前向きの変化 |
| 改善・一部改善 | 青系 | 通常の見直し |
| 縮小 | 琥珀系 | 規模縮小 |
| 完了 | グレー系 | 予定どおり終了 |
| 再構築 | 紫系 | 組み替え |
| 廃止 | 赤系 | 廃止 |

`--color-review-*-bg` / `--color-review-*-text` のペアで `@theme inline` に定義
（インラインカラーコード禁止規約のため、実装前にトークン追加を先に行う）。

## 7.5 PR2での決定記録（過年度データの制約）

- **R5評価書は断念**: 全冊がToUnicode欠落のサブセットフォント（埋め込みフォントに
  cmapテーブルも無い）で、OCR以外に復号手段がない。計画時に置いた判断ポイントに従い、
  予算推移はR5決算〜R8当初の4年分に縮退する
- **R6概要一覧はスキップ**: rotation=270の回転ページで表抽出が困難。過年度の検証は
  年度間の当初予算突合（R6評価書のR7当初 vs R7評価書のR7当初）で代替
- **R6の約10シートはスキャン画像**（文字レイヤーなし）で抽出不可。201事業中191件を抽出
- **評価対象は毎年一部の事業のみ**: R7の266事業のうちR6にも評価書があるのは53事業
  （exact 49＋similar 4、similar 4件は目視で正当性確認済み）。5年分の予算推移を
  出せるのはこの53事業で、残りはR7評価書由来の3点（R6決算/R7当初/R8当初）となる。
  なおKPI推移は様式1号自体にR2〜R12の目標・実績が載っているため全事業で複数年分ある
- **重複年度の値の優先順位**: R7当初の重複記載一致は37/52（71%）。不一致は組み替え・
  補正由来のため、seedでは最新年度評価書を正とし、過年度評価書からは重複しない
  R5決算・R6当初のみ取り込む

## 8. リスクと対応

- **PDF抽出のずれ**: 概要一覧との266件全件突合（crosscheck）で構造ずれは必ず検出
- **年度間の事業名マッチング**（PR2）: 正規化完全一致→同一部局内類似→手動overridesの
  3段階。未マッチ事業は予算推移が3点に縮退するだけで表示は破綻しない
- **AI生成コンテンツ規則**: 抽出はAI不使用のため対象外。図の要約等でAIを使う場合は
  seed前にユーザー確認必須（CLAUDE.md）

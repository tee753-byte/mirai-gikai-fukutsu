## 3. なぜ福岡市版（`d7500d7`）を土台にするのか

福津市版の土台として3つの候補があった。

| 候補 | 日付 | 作者 | 評価 |
|---|---|---|---|
| `kawasaki/develop` | 2026-03-20 | GondoTakashi | 構成は最小だが、**バクモンさんの作業ではない** |
| **福岡市版 `d7500d7`** | 2026-05-08 | **bakumon1107** | **採用** |

**採用理由**

1. **バクモンさんに質問しやすい。** 福岡市版はバクモンさん本人の作業。川崎版は別の方（GondoTakashiさん）の作業なので、質問先として自然でない
2. **命名規則が一致。** 福岡市版の `siteName` は `みらい議会＠福岡市`。福津版の `みらい議会＠福津市` と同じ形
3. **AI機能が既にオフ。** `aiChat: false` / `aiInterview: false` が設定済み（川崎版は両方 `true`）
4. **フェーズ1の「議会・会期一覧」ページがある**（`web/src/app/(main)/sessions/page.tsx`）。川崎版にはない
5. **市議会向けの表記。** 「市議会」「市民」「市長」の文言がそのまま使える（県版は県議会向けに全面修正されている）

### 注意：`fukuoka-city/develop` というブランチは存在しない

福岡市版は2026-05-29のコミット `8c9b276`「福岡市版設定・データを福岡県議会版に全面移行」で県版に置き換えられた。よって福岡市版は**その手前のコミット `d7500d7` として履歴上に存在する**。ブランチではなくコミットを指定して土台にしている。

### 6-5. フェーズ2機能の扱い（福岡市版ベース特有の論点）

福岡市版には、CLAUDE.mdでフェーズ2以降とされている機能が既に入っている。

| ページ | パス | 福津版フェーズ1での扱い |
|---|---|---|
| 予算の見える化 | `web/src/app/(main)/budget/` | **データを入れない＋バナーを明示的に隠す**（下記） |
| 一般質問 | `web/src/app/(main)/questions/` | **データを入れなければ自動で消える** |
| 議会・会期一覧 | `web/src/app/(main)/sessions/` | **使う**（フェーズ1の要件） |

**方針**: コードは消さずに残し、データを入れない＋導線を隠すことでフェーズ1の範囲に絞る。フェーズ2で使うときにコードを書き直さずに済む。

#### トップページの実装を調査した結果（`web/src/app/(main)/page.tsx`）

| バナー | 表示条件 | データなしのとき |
|---|---|---|
| 一般質問 | `{latestQuestionsSlug && ...}`（60行目付近） | **自動的に消える** ✅ |
| 予算概要 | `{activeSession?.slug && ...}`（61行目） | **消えない** ❌ |

`BudgetOverviewBanner`（`web/src/components/top/budget-overview-banner.tsx`）はデータ有無を確認しない単純なリンクで、文言も「令和8年度 各局の重点施策」がベタ書き。定例会が1つでもあれば表示されてしまう。

**採用する方法**: `site.config.ts` の `features` に **`showBudget` フラグを追加**し、`page.tsx` の予算バナーを `{siteConfig.features.showBudget && activeSession?.slug && (` で囲む。福津版では `false` にする。

- 理由: 本家も同じやり方をしている（`aiChat` / `aiInterview` / `showTeamMiraiSection`、県版では後に `showFactionStances` を追加）。CLAUDE.mdの「福津固有の変更は設定箇所に集約する」にも合致し、本家更新の取り込み時に衝突しにくい
- 併せて `PastSessionsSection` に渡す `budgetSessions` も、データがなければ空配列になるので予算リンクは出ない見込み（要目視確認）

## 8-2. ローカル構築で踏んだ既知の問題（2026-07-30）

### 問題1: Supabase最新版だとテーブル権限が付かず `pnpm seed` が失敗する

**症状**: `pnpm db:reset` の最後で `permission denied for table tags`。

**原因**: `npx supabase` が最新CLI（2.110.0）を取得し、`public` スキーマの新規テーブルに `anon` / `authenticated` / `service_role` の **DML権限（SELECT/INSERT/UPDATE/DELETE）が自動付与されなくなっている**。確認すると全テーブルで `Dxtm`（TRUNCATE/REFERENCES/TRIGGER/MAINTAIN）のみが付いていた。

**暫定対処**: `db:reset` の後に以下を実行する。

```powershell
docker exec supabase_db_mirai-gikai psql -U postgres -d postgres -c "GRANT ALL ON ALL TABLES IN SCHEMA public TO anon, authenticated, service_role; GRANT ALL ON ALL SEQUENCES IN SCHEMA public TO anon, authenticated, service_role; GRANT ALL ON ALL ROUTINES IN SCHEMA public TO anon, authenticated, service_role; ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES TO anon, authenticated, service_role;"
```

**恒久対応（要検討・バクモンさんに相談したい）**

- 案A: Supabase CLI のバージョンを固定する（バクモンさんが使っていた版を教えてもらう）
- 案B: 権限付与のマイグレーションを追加する（本番Supabaseでも同じ問題が起きる可能性が高いため、こちらが必要かもしれない）

> `pnpm db:reset` を実行するたびに権限が消えるので、暫定対処は都度必要。

### 問題2: 福岡市版のシードデータに川崎市の議案名が残っている

**症状**: `pnpm seed` が `Bill not found for content: 川崎市子ども医療費助成条例の一部改正` で失敗。

**原因**: `packages/seed/main/data.ts` の `bills` は福岡市の議案名に更新済みだが、`packages/seed/main/bill-contents-data.ts` の `bill_name` は**川崎市のまま**（同ファイル内に「川崎」が51箇所）。両者を突き合わせる処理で一致せず落ちる。

**福津版での対応**: どちらのファイルも福津市の議案データに全面差し替えるため、**書き換え時に両ファイルの `name` / `bill_name` を必ず一致させる**。これで自然に解消する。

# 委員会議事録アーカイブ設計

作成日: 2026-07-18

## 目的

福岡県議会の委員会（常任・特別・予算・決算）で「今回の委員会で何が話されてた？」を市民が分かりやすく知ることができるページを作る。会議ごとの内容が委員会単位で時系列に蓄積され、アーカイブとして残っていくことを狙いとする。

### コンテンツの基本方針

- **「どんな議論がなされたか」を伝えることが主目的**。発言者が誰かは見られるとよいが補助情報
- **政治に詳しくない中学生でも伝わる**表現を基準にする（Phase 2のAI要約プロンプトの根幹要件。専門用語には説明を付け、平易な言葉で議論の流れを示す）

- 対象: **現行委員会のみ**（旧委員会は対象外。ただし令和8年4月改組前の旧名称は同一系統として取り込む）
- 期間: **まずは2026年（令和8年）開催分のみ**。遡及は将来拡張
- 会議録原文は**全文をDBに格納**する
- 公開フローは一般質問（general_questions）と同じ `publish_status`（draft/published）+ AI生成内容はユーザー確認後に投入

## データソース: 会議録検索システム（dbsr.jp）

https://www.pref.fukuoka.dbsr.jp/ （福岡県議会 会議録検索システム）

実機検証で確認した仕組み:

| 項目 | 内容 |
|---|---|
| セッション | トップページ（`/index.php/`）アクセスで `DSNeo` cookieが発行され、ページ内リンクのURLパス `/index.php/<数値>` がセッションIDになる |
| 絞り込み検索 | セッション付きURLへ `Cabinet[]`（会議名）・`Class[]=3`（本文のみ）・`TermStartYear` 等をPOST。**1回のPOSTで複数条件を同時指定できる**（複数回に分けると条件が置き換わるので注意） |
| 一覧 | `?Template=list&Page=N` で15件ずつページ送り |
| 本文 | `?Template=doc-all-frame&VoiceType=all&DocumentID=<id>` でセッションに文書をセット後、`?Template=doc-page` で**全発言が1ページで返る** |
| 出典URL | セッションID部分は任意の数値でよい（アクセス時に新セッションが発行される）ため、`/index.php/1?Template=doc-one-frame&VoiceType=onehit&DocumentID=<id>` を安定URLとして保存できる |
| DocumentID | セッションをまたいで安定。重複取得防止・出典のキーに使う |

### 対象の会議（Cabinet ID）

- 常任委員会: 総務企画地域振興(3)・厚生環境(4)・県民生活商工(5)・農林水産(6)・県土整備(7)・建築都市(8)・文教(9)・警察(10)
- 議会運営委員会(19)（議案審査のある会議のみ収録）
- 特別委員会: 空港・交通インフラ(20)・子育て支援・人財育成(21)・再生可能エネルギー等(22)・国際化・多文化共生社会(23)・ワンヘルス・地方分権(24/25)・スポーツ立県(26)
- 予算特別委員会(46)・決算特別委員会(47)
- 旧名称の同一系統: 厚生労働環境委員会(12)→厚生環境、県民生活商工→商工労働（令和8年4月改組）

2026年開催の本文は**約51文書**（1文書30〜40KB）。

### スクレイピングのマナー

- 全リクエスト間に2秒のウェイト
- 429/503はRetry-After（なければ30/60/120秒）のバックオフ付きリトライ
- 連絡先入りUser-Agentを送出
- 取得済みDocumentIDはスキップ（再実行で差分のみ取得）

## データ設計

### committees（既存テーブルへの変更）

`committee_type` カラムを追加（standing / special / budget / audit / management、既定値 standing）。特別委員会等の行追加はPhase 2のシードで行う。

### committee_meetings（新規）

委員会の開催1回分＝会議録検索システムの「本文」1文書。

- `committee_id`: committees への FK（特別委等の未登録分があるため nullable）
- `committee_name` / `committee_slug`: 開催時点の名称と、名称変更をまたいで系統を束ねるスラッグ
- `source_document_id`（unique）/ `source_url`: 出典
- `summary`: 会議全体のAI要約（Phase 2）
- `speeches`（jsonb）: 発言単位の構造化データ `[{voiceNo, speakerLabel, speakerType, text}]`
- `raw_text`: 原文全文
- `publish_status`: draft / published

### committee_meeting_topics（新規）

会議内の議題1件分。委員会議事録は「『◯◯について』を議題といたします」で明確に区切られるため議題単位で構造化する。

**議題タイトル・発言範囲・発言者は正規表現による機械抽出でPhase 1から投入済み**（AI不使用）。抽出パターンは3種：

1. 調査特別委・常任委の報告事項:「『◯◯について』を議題といたします」
2. 議案審査: 「第◯号議案『◯◯』（所管分）を議題といたします」
3. 予算・決算特別委の部局別審査日: 「本日は、◯◯の審査を予定」→「◯◯の審査」を1議題扱い

議題が抽出されない会議は正副委員長互選のみの組織会議や採決中心の日で、実態と一致（2026年分では予算特別委の3会議のみ）。

- `title` / `summary` / `discussion_summary`: 議題名（機械抽出済み）・市民向け要約・質疑の流れ（要約はPhase 2でAI生成）
- `speakers`（jsonb）: 発言者一覧（機械抽出済み）
- `start_voice_no` / `end_voice_no`: 議題に対応する発言範囲（speeches の voiceNo）
- `bill_id`: **議案カード連携**（nullable FK）。常任委の付託議案審査を bills.committee_id で範囲を絞ってマッチング（Phase 3）
- `budget_overview_id`: **予算概要連携**（nullable FK）。予算特別委・常任委の予算審査議題を所管部局で紐付け（Phase 3）

## パイプライン

1. **スクレイパー** `packages/seed/fukuoka/scrape-committee-minutes.ts`
   - 純粋関数は `parse-committee-minutes.ts` に分離しテスト済み
   - 出力: `docs/data/committee-minutes/<年>/<開催日>_<スラッグ>_<DocumentID>.json`
2. **AI構造化・シード**（Phase 2）: seed-general-questions と同型のスキルで議題分割・要約生成 → ユーザー確認 → シード投入
3. **Webページ**（Phase 2〜3）:
   - `/committees` — 委員会一覧＋直近の会議（「今回の委員会で何が話されてた？」の入口）
   - `/committees/[slug]` — 委員会ごとの紹介＋会議アーカイブ（時系列）
   - 会議詳細 — 議題ごとの要約＋原文表示＋出典リンク
   - 議案カードに「委員会での審議」セクション追加（bill_discussions＝本会議質疑と並ぶ）
